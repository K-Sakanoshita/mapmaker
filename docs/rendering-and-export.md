# 描画・保存・設定の仕様

開発・設定を行う方向けの詳細です。利用者向けの特徴は[README](../README.md#主な特徴)、ファイルの配置と依存関係は[コード構成](code-structure.md)を参照してください。

## 描画の構成

編集画面にはMapLibreを使い、背景地図のベクトルタイルと、取得したOSMデータの編集モデルを組み合わせます。3D建物・屋根・樹木・壁・屋上通路などは共通の形状計算から描画し、タイルの建物との面の重なりを防ぎます。通常編集中はSVGを生成せず、SVG/PNG保存時に編集モデルとカメラからSVGを生成します。

`lib/renderers/maplibre/adapter.js` は既存の編集モデルをMapLibreのGeoJSONソース・レイヤー・Marker・Popupへ接続します。地物数だけGLレイヤーを増やさず、OSM layer・スタイル順・輪郭/内線・破線パターンごとにまとめます。カメラ操作中にSVGを生成し直すことはありません。背景地図はOSMFJのベクトルタイルを標準とし、既存のOSM/地理院ラスタタイルにも切り替えられます。WebGLに対応したブラウザーが必要です。

## 位置決めと手書き風プレビュー

位置決めはMapLibre GL JS 5.20.0で行います。「2D」「3D」で傾きを0度／30度（ズーム別の上限を適用）に切り替え、位置・回転・傾きを決めてから「地図をカスタマイズ」を押します。編集中は地図の移動・ズーム・回転・傾きをロックします。地物のクリック編集は2D表示で行い、3D表示ではクリック判定を行いません。既存の地図を残したまま追加レイヤーを準備するため、地図全体が空白になる切り替えを避けます。アイコンやラベルはDOM上で移動・編集でき、保存時に合成します。

手書き風の塗りを「なし」以外にすると、保存と同じSVG処理から画像プレビューを作り、地図に重ねます。メニューの配置は変えず、色・線幅・アイコン追加・用紙サイズ変更・リセットなどを利用でき、操作後はプレビューを更新します。地図上の通常クリックは抑制し、手動ピンを追加する間は配置操作を受け付けます。

手書き風の塗りを選ぶと、粗さ・ゆがみを調整する小さなダイアログを表示します。閉じるボタン・Esc・外側のクリックで閉じ、塗りの選択を変更すると再表示します。閉じても選択した塗りと調整値は保持し、「なし」で通常表示に戻します。粗さ・ゆがみは数値をすぐに表示し、最後のスライダー操作から1秒後にプレビューへ反映します。

## ズーム別の傾き上限

位置決め時の傾き上限は `data/config-user.jsonc` の `default.maxPitchByZoom` で指定します。`{"zoom": 14, "pitch": 25}` のような組を並べ、ズーム14以下で25度、16で40度、18以上で55度を初期値としています。指定点の間は線形補間し、ズームアウト時に現在の傾きが上限を超えれば下げます。URLから復元した表示にも適用します。順序は自由で、同じズームは後の指定を使います。ズーム・角度が数値でない項目や角度が0〜180度の範囲外の項目は無視し、有効な指定がなければ一律50度になります。

## 建物・屋根・建物の部分

建物の高さは `height`（m、単位なし、ft）、`building:levels × 3m`、既定の3mの順で決めます。不正な高さは階数または既定値へフォールバックします。`data/config-user.jsonc` の `default.birdseye` で既定高さ・階高・初期傾斜を変更できます。

3Dでは、長方形に近い輪郭の `roof:shape=gabled`（切妻）・`hipped`（寄棟）・`pyramidal`（ピラミッド型）を画面とSVG/PNGで共通の形状として表現します。屋根は平屋根と同じ基本色を使い、北西からの固定光による斜面の陰影を最大4％に抑えて、色に設定された透明度を保ちます。背面の屋根面を省き、SVGでは棟線・軒線・壁の輪郭を一度ずつ描いて線の重複を抑えます。`building:part` も建物として取得・描画します。`roof:height`、`roof:levels × 階高`、既定3mの順で屋根の高さを決め、`height` があれば屋根を含む総高さとして軒高を差し引きます。`height` がない場合は階数または既定の建物高さへ屋根高さを加えます。

`building:part` は部分ごとの `height`（地面から上端）、`min_height`（地面から下端）、`building:levels`・`building:min_level` を反映します。m/ft指定に対応し、階数は設定された階高で換算します。下端だけ分かる場合は、その上に既定の一階分を表示します。上端が下端より低いなど不正な部分は3Dへ出力しません。

`type=building` リレーションの `outline` / `part` を優先して対応付け、リレーションがない場合は中庭と境界交差を除いた包含判定で、最も小さい外周へ関連付けます。外周の高さ範囲に重なり、その下端から始まるか全体の平面形状を覆う有効な部分がある場合は、外周を3Dで描きません。下端より高い位置から始まる小さな部分だけの場合は本体も残します。大屋根リングのような環状の建物も、上部の小さな部分だけで全体が消えないようにします。2Dでは外周を表示して部分の重複を抑えます。外周が取得できない部分は単独で表示します。元のOSMタグ・形状は保持し、画面・手書き風・SVG/PNGで同じ選択を使います。SVG/PNGでは同じ外周に属する部分の面ごとに投影後の奥行きを比較し、隠れる面・輪郭線をベクターのマスクで除きます。透明度を保ちながら、内部の壁が重なって透けることを防ぎます。手書き風では面だけを変換し、隠面マスクを保持します。部分どうしの共有面を削除するブーリアン合成までは行いません。タグの意味は[Simple 3D Buildings](https://wiki.openstreetmap.org/wiki/Simple_3D_Buildings)を参照。

棟の向きは `roof:orientation=along/across`（長辺に対して平行/直交）で選び、`roof:direction` があれば屋根面が下る方角として優先します。数値の角度または16方位を読み、輪郭の2軸に近似します。中庭付き・不整形・未対応の屋根形状や、屋根が総高さを超えるなど不正な寸法は平屋根へ戻します。タグ仕様は [roof:direction](https://wiki.openstreetmap.org/wiki/Key:roof:direction)、[roof:height](https://wiki.openstreetmap.org/wiki/Key:roof:height) を参照。

## 樹木・季節・形状の選択

編集パネルの「季節」で通常・春・秋を手動選択できます。`data/leyers.jsonc`の`seasons`で樹種別の葉色と森林の混色先・混色率を設定します。春は桜を淡いピンク、秋は桜を赤茶・イチョウを黄色にし、森林は`leaf_cycle`に応じて控えめに変化します。常緑林とモノクロ・ぬりえパレットは変えません。日付による自動変更は行いません。

3D形状の選択は`data/leyers.jsonc`の`model3D`で管理します。`tree`（樹冠）、`roof`（屋根）、`barrier`（壁・生垣・フェンス・ロープ）の各`rules`を上から判定し、最初に一致した`model`を使います。未一致時は`defaultModel`を使います。条件の書き方と拡張例は[3Dモデル選択ルール](model3d-rules.md)を参照してください。樹木の寸法・色は引き続き`pointStyle.tree`で管理します。

樹種タグのある桜は横に広い丸い樹冠、イチョウは上部が広がる樹冠で表現します。色は既存の樹木設定を引き継ぎます。その他の樹木の樹冠は先端を小さな球面で丸めた円錐形とし、斜面へ滑らかにつなげて、画面とSVG/PNGで共通の幹・樹冠を使います。幹を太くし、樹冠の開始高さを全高の45％に上げて斜めから幹が見えるようにしています。樹冠の底辺は2Dの樹木記号より15％細くし、全高・高さタグの解釈・2D表示は維持します。

## 生垣・フェンス・ロープ・旗竿・擁壁

生垣（`barrier=hedge`）は3D表示時に幅0.5m・既定高さ1.0mで立体化します。`height` がある場合はその値（m / ft）を優先します。画面とSVG/PNGで同じ形状・高さを使い、閉じた生垣も内側を塗り潰しません。色は現在のレイヤー設定を使い、2D表示は従来どおりです。

フェンス（`barrier=fence`）は支柱・横棒・菱形の金網、ロープ（`barrier=rope`）は支柱とたるんだロープで表現します。背景が透ける共通メッシュを画面とSVG/PNGで使い、`height`（m / ft）がない場合はフェンス1.5m、ロープ1mとします。フェンスは低倍率で網目を見分けやすいよう表示高さ・間隔・線幅を調整し、元の高さタグと形状を保持します。

旗竿（`man_made=flagpole`）は既存の施設カテゴリに含めて自動取得し、「3D化」で支柱と折れ目のある単色の旗を表示します。アイコン追加操作や専用パレットは不要です。`height`（m / ft）を優先し、未指定時は6mとします。カラーパレットでは`flag:colour`の基本色名・6桁の16進色を反映し、モノクロ・ぬりえでは各パレットの色を使います。`flag:type=national`と対応する`country`コードがある場合は国旗の図柄を優先し、国コードだけの場合や団体旗・未対応コードでは単色を維持します。249のISOコードとXKに対応し、素材は使用する国のものだけを読み込みます。保存時はSVG素材を埋め込み、画面とSVG/PNGで旗の折れ目に沿って図柄を表示します。モノクロ・ぬりえでは従来の単色を使います。素材は[flag-icons 7.3.2](https://github.com/lipis/flag-icons)のMITライセンスに従って同梱しています。設定は`data/leyers.jsonc`の`pointStyle.flagpole`で管理し、画面とSVG/PNGで同じ形状を使います。

擁壁（`barrier=retaining_wall`）は地面に沿う破線と、ウェイの右側（低い側）へ向く小さな三角で表現します。2D・3D画面とSVG/PNGで共通の記号を使い、ズーム後も三角の大きさと間隔を調整します。地面や壁を立体化せず、高さタグは記号の形に使いません。

## アイコン・目印・言語・万博モード

アイコン追加時のサイズは「小・標準・大」とプレビューで選び、詳細設定でpx単位の数値を指定できます。小12px・標準14px・大18pxで、初期値は標準14pxです。

目印ピンのコメントには、画面上でPOI名と共通の半透明な白背景を付けます。Wikipedia記事は右上の✕で記事だけを閉じられ、元のマーカーは残ります。記事の位置・寸法・文章の折り返しを画面とSVG/PNGで揃え、✕は書き出しに含めません。

初回にルートURLを開いたときはブラウザーの優先言語に応じて日本語・英語へ振り分けます。ヘッダーの言語メニューで選んだ言語は次回以降も優先し、切り替え時は地図位置とクエリーを保持します。英語ページのURLは`en/`です。

全体メニューの「EXPO2025 万博の地図」は会場へ移動するだけで、編集は自動で始めません。`?preset=expo2025`で2025年10月13日版の背景地図と、道路・建物を統合した第4版（`2026-10-19-4`）の[万博マニアックマップの公開OSM JSON](https://k-sakanoshita.github.io/expo2025-maniacs/data.html)を選びます。「地図をカスタマイズ」やアイコン追加を操作した際に、この公開データを取得します。取得失敗時に現在のOSMデータへ切り替えることはありません。メニュー先頭に「通常の地図」「EXPO2025 万博の地図」を並べ、表示中の地図にチェックを付けます。万博モードの移動・ズームアウトを夢洲周辺に制限し、地図情報欄にモード名を表示します。「通常の地図」へ戻る際も表示言語と地図位置を保持します。初期位置・背景地図・移動範囲・取得先は`data/config-user.jsonc`の`mapPresets`で管理します。

## SVG/PNG保存と制限

SVG/PNG保存にはMapLibreの公開カスタムレイヤー描画APIから取得したカメラ行列を使い、画面で調整した向き・傾斜・選択範囲を反映します。SVGは建物ごとのグループ内に屋根と側面を独立したパスとして保持し、文字とアイコンもベクターとして保存します。カメラ後方や視錐台の外の地物は遠近除算の前に切り取り、遠方の水面などが反転して用紙を覆うことを防ぎます。SVGの重なりは奥から手前への描画順による近似です。地形の起伏、曲面や複雑な屋根、部分形状どうしの厳密な立体合成、道路の立体交差や複雑に交差する建物の厳密な遮蔽には対応していません。

## データ取得と失敗時の動作

取得判定用ズーム14未満では`data/overpass-system.jsonc`の各地物の`overpassLowZoom`・`tagsLowZoom`を使い、主要道路・河川・本線鉄道・森林・水面などを絞って取得します。通常の取得条件は14以上で使います。`data/config-system.jsonc`の`system.MapData`で切り替え倍率、受信バイト数・要素数・座標数の上限と簡略化を調整できます。受信・JSON解析・変換はWorkerで行い、上限超過時は再試行せず拡大を案内します。低ズームの線・単一ポリゴンは共有頂点や穴を保ちながら簡略化し、検査に失敗した形状は維持します。MultiPolygonは一直線上の冗長頂点のみ削減します。許容誤差は初期値0.5 CSS pxを上限とし、A3・300dpi相当の保存時にも細部を保つようさらに絞ります。設定した解像度を超える拡大出力では細部の再現に限界があります。

地物の取得開始判定は、`system.MapData.viewportZoom`で地図の表示サイズに応じて補正します。各地物の`zoom`設定は変更せず、補正後の値を取得対象・低ズーム用の取得条件・拡大案内・編集項目に共通で使います。

```json
"viewportZoom": {
  "enabled": true,
  "referenceWidth": 1024,
  "referenceHeight": 768,
  "maxAdjustment": 1
}
```

基準サイズは地図のCSSピクセル数です。ブラウザー全体や端末の物理解像度ではありません。実際の取得bboxを現在のズームのMercatorピクセル面積へ換算し、`0.5 × log2(基準面積 / 取得面積)`をズームに加え、`maxAdjustment`の範囲に制限します。傾き・回転による取得範囲の広がりも反映します。bboxが無効な場合は地図の表示サイズを使い、表示サイズや設定が無効な場合は補正しません。初期値は基準1024×768・最大±1段で、`enabled: false`で従来の判定に戻せます。

画面のズーム値、描画の線幅、傾き上限、形状簡略化には補正前のズームを使います。取得判定は小数1桁に丸め、取得に成功した時点の値を編集終了まで保持します。編集中のパネル開閉や画面サイズ変更で取得済みの編集項目は変わりません。取得量の上限は従来通り維持します。

Overpass取得は1試行150秒を上限とし、設定されたサーバーを最大2巡します。接続失敗・HTTP 408/429/5xxでは次のサーバーへ切り替え、待機を1秒から最大5秒まで増やします。Retry-After（秒数または日時）が5秒以内なら従い、それより長い待機指定では自動再試行を止めます。それ以外のHTTP 4xx、キャンセル、データ変換エラーは再試行しません。CSV取得は30秒で打ち切ります。失敗時は処理中表示を終了し、ダイアログを閉じて再試行できます。
